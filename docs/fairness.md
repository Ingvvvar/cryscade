# Проверка раунда — разобранный пример

Раунд выбирается из книги исходов (§5) по HMAC (§7). Сервер заранее фиксирует секрет и до игры публикует
обязательство — его SHA-256. Раунд с номером nonce — запись книги, на которую указывает
HMAC-SHA256(секрет, `сид игрока:nonce:counter`). После смены сида секрет раскрыт, и любой может пересчитать выбор сам: сервер
не мог подобрать раунд под игрока — секрет был связан обязательством, а сид игрока сервер не выбирает.

Ниже — настоящий раунд e2e-сборки (`npm run build:e2e`, Chromium 153, 2026-09-30): три спина, первый выигрышный — третий
(nonce 2); потом `rotateSeed` раскрыл секрет. Каждый шаг можно пройти руками: openssl и Python, без кода игры; движок
понадобится только на последнем шаге.

## Данные раунда

| Что | Значение |
| --- | --- |
| Раунд | `f5126499-5872-404c-b9f6-83ea1f84cf0d`, ставка 1.00 (100 минимальных единиц), выигрыш 3.60 (360) |
| Сид игрока | `368b3992e69d7702` |
| nonce | `2` |
| Обязательство (до игры) | `2e2bb4e58966f22a7cdd8eed6d6a7b4030abef3cf5b0cead067218feb9d2e8be` |
| Секрет (раскрыт сменой сида) | `6ce21799a457eefb0c1e6532af8132dc4fdf902e4ff9459c36f3088adfc5e48d` |
| Книга | `public/books/base.v1.bda29460a5ec.bin.gz`, W (сумма весов) = `6534666741287` — `weightTotal` в `public/books/base.v1.json` |
| Индекс, записанный сервером | `18298` |

Где игрок берёт эти данные: с фазы 7 — диалоги «Честность» и «История». До них — IndexedDB `cryscade` (DevTools →
Application → IndexedDB): раунд — хранилище `rounds` (поля `clientSeed`, `nonce`, `commitment`, `bookIndex`), секрет —
`secrets` (после смены сида у него `revealedAt`).

## Шаг 1. Секрет — тот, что обещан

SHA-256 байт секрета должен совпасть с обязательством, опубликованным до раунда.

```sh
printf '%s' 6ce21799a457eefb0c1e6532af8132dc4fdf902e4ff9459c36f3088adfc5e48d | xxd -r -p | openssl dgst -sha256
# 2e2bb4e58966f22a7cdd8eed6d6a7b4030abef3cf5b0cead067218feb9d2e8be
```

OpenSSL 3 печатает перед дайджестом `SHA2-256(stdin)=`, LibreSSL из macOS (`/usr/bin/openssl`) — только дайджест; значение
одно. Так же и на шаге 2.

## Шаг 2. HMAC

Ключ — байты секрета, сообщение — ASCII-строка `сид игрока:nonce:counter`, counter начинается с 0.

```sh
printf '%s' '368b3992e69d7702:2:0' \
  | openssl dgst -sha256 -mac HMAC -macopt hexkey:6ce21799a457eefb0c1e6532af8132dc4fdf902e4ff9459c36f3088adfc5e48d
# e8b522795c80453e9c45e9501b7a9509c8ef4a79f9723ef04d1fa588ac852da6
```

## Шаг 3. Первые 8 байт — число

Первые 16 знаков hex — `e8b522795c80453e` — это uint64 big-endian:

```sh
python3 -c 'print(int("e8b522795c80453e", 16))'
# 16768346692222207294
```

## Шаг 4. Граница равномерности

Остаток от деления на W равномерен только ниже границы floor(2^64 / W) · W: верхний неполный кусок отбрасывается, и тогда
берут counter 1 (сообщение `368b3992e69d7702:2:1`) и так далее. Здесь граница отбрасывает 656 396 772 881 значений из 2^64 —
примерно один раунд на 28 миллионов.

```sh
python3 -c 'W = 6534666741287; q = 2**64 // W; print(q, q * W)'
# 2822905 18446743417312778735
```

16768346692222207294 меньше 18446743417312778735 — значение берём с counter 0.

## Шаг 5. Точка на весах книги

```sh
python3 -c 'print(16768346692222207294 % 6534666741287)'
# 6288742029361
```

## Шаг 6. Индекс книги

Записи книги идут подряд, у каждой — вес. Выбрана первая запись, чей накопленный вес (сумма весов с начала книги по неё
включительно) больше точки. Сначала — что книга та самая: SHA-256 её несжатых байт вшит в сборку игры, а первые 12 знаков
стоят в имени файла.

```sh
gunzip -c public/books/base.v1.bda29460a5ec.bin.gz | shasum -a 256
# bda29460a5ec0947c65bd36ae1e3ebcd22089e71b9423c2d373139ef77f48555  -
```

Формат (§5): `CRYB`, версия u16, число записей u32, W u64, дальше записи по 12 байт — сид u32, выплата в сотых ставки
(payX100) u32, вес u32; всё little-endian.

```sh
python3 - <<'PY'
import gzip, struct
raw = gzip.open('public/books/base.v1.bda29460a5ec.bin.gz').read()
count = struct.unpack_from('<I', raw, 6)[0]
point, running = 6288742029361, 0
for index in range(count):
    seed, pay, weight = struct.unpack_from('<III', raw, 18 + 12 * index)
    if running + weight > point:
        print(index, running, running + weight, seed, pay, weight)
        break
    running += weight
PY
# 18298 6288699858027 6288765363985 27781324 360 65505958
```

Индекс 18298: накопленный вес до записи 6288699858027 ≤ 6288742029361 < 6288765363985 с ней. Тот же индекс сервер записал в
раунд.

## Шаг 7. Запись — раунд и выигрыш

Запись 18298: сид движка 27781324, выплата 360 сотых ставки (3.60×). Выигрыш — floor(ставка × payX100 / 100), целыми
минимальными единицами (§4.6): floor(100 × 360 / 100) = 360, то есть 3.60 при ставке 1.00 — ровно выигрыш раунда.

Что сид 27781324 даёт именно этот раунд, проверяет движок: инструмент ниже переигрывает его, а ссылка `?replay=book:18298`
показывает запись в любом браузере — те же события, что `?replay=round:f5126499-5872-404c-b9f6-83ea1f84cf0d` в браузере, где
раунд сыгран.

## Всё одной командой

```sh
# раскрытый секрет демонстрационного раунда — ничего не защищает
node tools/fairness/verify.ts --secret=6ce21799a457eefb0c1e6532af8132dc4fdf902e4ff9459c36f3088adfc5e48d \
  --client-seed=368b3992e69d7702 --nonce=2 --commitment=2e2bb4e58966f22a7cdd8eed6d6a7b4030abef3cf5b0cead067218feb9d2e8be
```

```text
Книга public/books/base.v1.bda29460a5ec.bin.gz: записей 58354, W = 6534666741287
1. SHA-256(секрет) = 2e2bb4e58966f22a7cdd8eed6d6a7b4030abef3cf5b0cead067218feb9d2e8be — совпадает с обязательством
2. counter 0: HMAC-SHA256(секрет, «368b3992e69d7702:2:0») = e8b522795c80453e9c45e9501b7a9509c8ef4a79f9723ef04d1fa588ac852da6
   первые 8 байт e8b522795c80453e = 16768346692222207294
   граница floor(2^64 / W) · W = 2822905 · 6534666741287 = 18446743417312778735: меньше — значение берём
   точка = 16768346692222207294 mod 6534666741287 = 6288742029361
3. индекс книги 18298: накопленный вес до записи 6288699858027 ≤ точка 6288742029361 < 6288765363985 с записью
4. запись 18298: сид 27781324, выплата 360 сотых ставки, вес 65505958; движок по сиду — 360, совпадает
5. выигрыш при ставке 100: floor(100 · 360 / 100) = 360 минимальных единиц
Повтор записи: ?replay=book:18298
```

Инструмент зовёт те же чистые функции, что сервер (`src/server/fairness.ts`); не сошлось что-то — код выхода 1. Числа этого
примера держит тест `tests/unit/tools/fairness-verify.test.ts`, выбор каждого раунда e2e сверяет с пересчётом в Node
`tests/e2e/fairness.spec.ts`.
