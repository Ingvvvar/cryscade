# Правила проекта Cryscade

Спецификация — `TASK.md`: в начале фазы читай нужные разделы, не весь файл каждый раз. Этот файл грузится в каждую сессию, поэтому он короткий.

## Порядок работы
- План → моё одобрение → код. На каждой фазе и каждом подходе.
- Один коммит на шаг, стоп после него. Следующий шаг сам не начинаешь.
- Уборку и рефакторинг, о которых не просили, не делаешь. Заметил — скажи словами.
- `git push` — только с моего слова в текущем шаге.
- Остаток лимита плана ты не видишь и `/usage` вызвать не можешь — спрашивай меня.
- Про свою версию и настройки не гадай — проверяй командой.
- В конце сессии обнови `SESSION.md` (он в `.gitignore`): последний коммит, что закрыто, что открыто, первый шаг следующей сессии.
- Коммиты — семантические, на английском, одной строкой.

## Агенты и лимиты
- Агенты и workflow — только после моего подтверждения, что лимита осталось не меньше половины. Не знаешь остаток — спроси; «на всякий случай» не запускай.
- Одновременно не больше 4 (потолок стоит в `.claude/settings.json`), за прогон не больше 8.
- Только непересекающиеся файлы; по умолчанию read-only — аудит, ревью, поиск. Параллельная запись — только в отдельных worktree и с моего слова.
- `src/core/model/**`, `src/protocol/**` и общие типы правит только основной контекст.
- Задача меньше чем на три файла — один контекст. Agent teams не используем.
- `ultracode` — только там, где он помечен в `TASK.md`. По умолчанию `/effort high`; `ultrathink` — точечно на трудные места.

## Код
- npm, не Bun. Версии точные; мажорные обновления — отдельной задачей.
- TypeScript strict, `any` запрещён; не выводится тип — опиши явно.
- Границы модулей из `TASK.md` §3 — контракт: их держат тест и линтер, нарушение откатывается.
- В `src/core/**` нет `Math.random`, `Date.now`, `performance.now`, `new Date()`, `crypto`, DOM.
- Деньги — только целые минимальные единицы.
- Pixi — только v8: сверяйся со скиллами PixiJS и release notes установленной версии, а не с памятью.
- Хранилище переживает пустое, испорченное и недоступное состояние.

## Тесты
- Ожидание — литерал или независимое вычисление, никогда та же константа, которую тест закрепляет.
- Закрепляй не только формулу, но и место, где её вызывают.
- Каждую новую проверку докажи мутацией: сломал код → тест красный → откатил. Назови мутацию в отчёте.
- Тест, который что-то сканирует, проверяет, что нашёл больше нуля.

## Замеры
- Инструменту не верь, пока он не поймал положительный контроль.
- Синтетический ввод — чтобы привести игру в состояние; путь ввода мерить только кликом по координате.
- Производительность — только на GPU: строку рендерера печатать, на SwiftShader не мерить.
- Худшее из N прогонов, не лучшее. Стенд — не телефон.
- Про картинку и звук не пиши «работает» — пиши, что мне посмотреть или послушать.

## Проверка
- После правок — typecheck, lint, test; перед коммитом — всё из готовности шага в `TASK.md`.
- «Готово» — только после зелёных команд. Упало — скажи, что именно, соседний код заодно не чини.
